# PhotoMap — что нужно от Go API

Этот список описывает работу первой версии интерфейса. Имена методов, маршруты и форматы ниже предложены для согласования. Макет сейчас использует демонстрационные данные в браузере. MapLibre получает базовую карту из OpenFreeMap. Сервер PhotoMap хранит снимки и отдаёт данные для меток.

## 1. Карта и просмотр снимков

| Запрос | Что нужно вернуть |
|---|---|
| `GET /api/series` | Список серий опубликованных снимков. Каждая запись содержит ID центра, координаты, название, место, количество фото, сумму звёзд и миниатюру. Для первой версии можно вернуть все серии. |
| `GET /api/series/{id}` | Те же поля и отсортированные карточки снимков в серии. Если серии больше нет после пересчёта, вернуть `404`. |
| `GET /api/photos/{id}` | Публичную карточку с текущим `seriesId`. Этот запрос используется и при открытии карточки с карты, и при поиске по ID. Для скрытого, удалённого, отклонённого, ожидающего проверки или отсутствующего снимка вернуть `404`. |
| `GET /api/photos/{id}/image` | Изображение опубликованного снимка. При изменении статуса публичная ссылка и миниатюра перестают выдавать файл. Автор и модератор могут получать разрешённые изображения через авторизованные маршруты. |

Для метки предлагаю `id` (ID снимка в центре серии), `coordinates`, `title` (название объекта), необязательное `place` (например, «Париж, Франция»), `photoCount`, `stars` и `thumbnailUrl`. Ответ `GET /api/series/{id}` дополнительно содержит массив `photos`.

У карточки фото нужны `id` (целое число), `title`, `description`, `place`, `coordinates` (массив `[долгота, широта]`), `year`, необязательный `endYear`, `imageUrl`, необязательные `sourceName` и `sourceUrl`, `authorId`, `authorName`, `stars` и текущий `seriesId`. Для вошедшего зрителя добавить `starredByMe` и `reportedByMe`.

Правила серий:

1. Брать только опубликованные снимки. Отсортировать по звёздам от большего к меньшему, затем по возрастанию ID.
2. В этом порядке выбрать центры. Снимок становится центром, если в радиусе **до 100 м включительно** ещё нет выбранного центра.
3. Привязать каждый снимок к ближайшему центру в пределах 100 м. При одинаковом расстоянии выбрать центр с меньшим ID.
4. Сортировать фото внутри серии по году или началу диапазона, затем по ID. Возвращать число фото и сумму звёзд по всей серии. Размер метки ограничивает интерфейс.

## 2. Вход, загрузка и кабинет

| Запрос | Что должен сделать сервер |
|---|---|
| `POST /api/auth/register` | Создать пользователя. Предлагаемые поля `name`, `email`, `password`. Самостоятельная регистрация выдаёт обычную роль. |
| `POST /api/auth/login` | Проверить учётные данные и открыть сессию. Вернуть `id`, `name` и роль `user` или `moderator`. |
| `GET /api/auth/me`, `POST /api/auth/logout` | Получить текущего пользователя или завершить сессию. Для гостя `/me` возвращает `401`, карта остаётся доступна. |
| `POST /api/photos` | Принять `multipart/form-data` с файлом `image` и полями `title`, `place`, `description`, `longitude`, `latitude`, `year`, необязательными `endYear`, `sourceName`, `sourceUrl`. Вернуть `201` с ID и статусом `pending`. |
| `GET /api/me/photos` | Список публикаций текущего пользователя со статусами, включая ожидающие и повторно проверяемые снимки. Для счётчиков кабинета учитывать опубликованные фото и их звёзды. |
| `DELETE /api/me/photos/{id}` | Удалить свою публикацию из публичного доступа. Сохранить запись, файл и историю модерации, пометить снимок как `removed`. |

Точка относится к **объекту в кадре**. Год обязателен. Если передан `endYear`, он не может быть раньше `year`, разница не больше 50 лет. Сервер проверяет координаты, обязательные поля, безопасную схему ссылки и действительный формат файла. Допустимые размеры файлов согласуем перед подключением. Ограничение макета в 1 МБ связано с хранением загрузок в браузере.

Для приложения с одним доменом подойдёт сессия в cookie с `HttpOnly`, `Secure` в HTTPS и подходящим `SameSite`. Сервер проверяет права по сессии на каждом закрытом маршруте и защищает запросы, меняющие данные, от CSRF. Выбор роли в макете нужен для показа экранов.

## 3. Звёзды, жалобы и модерация

| Запрос | Что должен сделать сервер |
|---|---|
| `PUT /api/photos/{id}/star`, `DELETE /api/photos/{id}/star` | Поставить или снять звезду текущего пользователя. Повтор того же запроса сохраняет результат. Вернуть `stars` и `starredByMe`. |
| `POST /api/photos/{id}/reports` | Сохранить жалобу от текущего пользователя. При повторной жалобе вернуть `409` и код `already_reported`. При третьей активной жалобе скрыть снимок и перевести на повторную проверку. |
| `GET /api/moderation/photos?status=pending,review` | Выдать очередь новых и повторно проверяемых снимков с их данными. Экрану также нужны списки опубликованных и снятых снимков. |
| `PATCH /api/moderation/photos/{id}` | Сохранить исправления полей карточки, включая координаты, если они изменились. Статус сохраняется. |
| `POST /api/moderation/photos/{id}/decision` | Принять действие `approve`, `reject`, `restore` или `unpublish`. Вернуть карточку с итоговым статусом. |

| Статус | Кто видит снимок | Что с ним можно сделать |
|---|---|---|
| `pending` | Автор и модератор | Модератор может исправить, одобрить или отклонить. |
| `published` | Все | Можно поставить звезду и пожаловаться после входа. Модератор может исправить или снять с карты. |
| `review` | Автор и модератор | Модератор может исправить, восстановить или отклонить. |
| `rejected` | Автор и модератор | Модератор может исправить или восстановить. |
| `removed` | Снимок исключён из пользовательских списков и публичного API | Удаление автором завершает жизненный цикл публикации. |

Жалоба уникальна по паре «пользователь + фото» на весь срок жизни публикации. Порог в три жалобы считается по ещё не рассмотренным жалобам от разных пользователей. После решения модератора этот счётчик обнуляется, история сохраняется. Восстановленный снимок сохраняет ID и звёзды. Звезда тоже уникальна по паре «пользователь + фото», её можно отменить и поставить заново.

Скрытие, изменение статуса и обновление выдачи серий должны согласованно отражаться в API. После вступления решения в силу запросы к публичной карточке и файлу уже возвращают `404`. Для медиа важно исключить выдачу скрытого снимка из кэша PhotoMap.

## 4. Обновления карты

Для первой версии подойдёт `GET /api/events` с Server-Sent Events. После публикации, скрытия, удаления, изменения координат, деталей опубликованного снимка или звёзд сервер посылает событие `map.updated` с номером ревизии и, если известно, ID затронутых снимков. После события клиент заново запрашивает список серий и открытую карточку. При переподключении клиент повторяет запросы, чтобы учесть пропущенные обновления. В публичном событии достаточно ID снимков, для которых изменилась публичная выдача.

Если открытое фото перешло в другую серию, интерфейс сохраняет выбранный снимок и показывает новую серию по `seriesId`. Если фото скрыто, `404` переключает карточку на «Фото недоступно». Обновления после модерации нужны также для кабинета автора и очереди модератора. Можно отправлять отдельное событие в авторизованном канале или обновлять эти экраны при открытии и после действия.

## 5. Ошибки и порядок подключения

Предлагаемый формат ошибки: `{"code":"invalid_year_range","message":"Диапазон не может превышать 50 лет","fields":{"endYear":"Проверьте конечный год"}}`. Поле `fields` нужно для ошибок формы. В интерфейсе также нужны `401` для отсутствующей сессии, `403` для запрета операции, `404` для недоступного снимка, `409` для конфликта состояния, `413` для превышения размера файла и `422` для ошибок полей.

1. Сначала подключить `GET /api/photos/{id}` и изображение. Нужны одна опубликованная и одна неопубликованная запись, чтобы проверить `200` и `404`.
2. Подключить выдачу серий, затем вход, загрузку, кабинет и решение модератора.
3. Добавить звёзды, жалобы и события. В двух вкладках проверить публикацию, смену центра серии, скрытие после третьей жалобы и восстановление под прежним ID.

Публичные профили с аватарами, управление пользователями, администраторские логи и фильтр по времени относятся к следующему этапу.
