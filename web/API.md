# PhotoMap API

Интерфейс обращается к `/api` на том же домене. Сессию хранит сервер в cookie `session_token` с флагом HttpOnly. JSON отправляется с `Content-Type: application/json`, запросы выполняются с `credentials: 'include'`. У multipart-запроса границу и заголовок формирует браузер.

## Сессия

| Запрос | Данные и результат |
| --- | --- |
| `POST /api/auth/register` | `name`, `email`, `password`. Сервер создаёт пользователя и открывает сессию. |
| `POST /api/auth/login` | `email`, `password`. Сервер открывает сессию. |
| `GET /api/auth/me` | `id`, `name`, `email`, `role`. Для гостя ответ `401`. Только роль `moderator` открывает панель модерации. |
| `POST /api/auth/logout` | Завершение сессии, ответ `204`. |

## Снимки и серии

| Запрос | Данные и результат |
| --- | --- |
| `GET /api/series` | Сводки серий с полями `id`, `coordinates`, `title`, `place`, `photoCount`, `stars` и `thumbnailUrl`. |
| `GET /api/series/{id}` | Сводка и массив `photos` в порядке датировки и ID. |
| `GET /api/photos/{id}` | Публичная карточка, включая `seriesId`, ссылки на файл и миниатюру, а для вошедшего пользователя ещё `starredByMe` и `reportedByMe`. |
| `GET /api/photos/{id}/image`, `GET /api/photos/{id}/thumbnail` | Файл опубликованного фото. Миниатюра может возвращать оригинал. |

Метка открывает серию, затем снимок в её центре. При поиске по ID интерфейс сначала получает карточку, затем её текущую серию. Координаты в ответах идут в порядке `[долгота, широта]`. Неопубликованные карточки и файлы недоступны по публичным адресам, даже если пользователь вошёл.

## Загрузки и кабинет

| Запрос | Данные и результат |
| --- | --- |
| `POST /api/photos` | Multipart с файлом `image` и полями `title`, `place`, `description`, `longitude`, `latitude`, `year`. Необязательные поля: `endYear`, `sourceName`, `sourceUrl`. Ответ `201`, статус снимка `pending`. |
| `GET /api/me/photos` | Снимки автора со статусами, без удалённых. |
| `DELETE /api/me/photos/{id}` | Снимок получает статус `removed`, ответ `204`. |

Поддерживаются JPEG, PNG и WebP до 10 МиБ и 40 миллионов пикселей. Год положительный. Конец диапазона не раньше начала и не дальше чем на 50 лет. У закрытых карточек интерфейс использует `imageUrl` и `thumbnailUrl` из ответа, чтобы сервер мог проверить доступ к файлу.

## Модерация и реакции

| Запрос | Данные и результат |
| --- | --- |
| `GET /api/moderation/photos` | Очередь `pending` и `review`. Запрос с `?status=published` или `?status=rejected` показывает соответствующий раздел. |
| `GET /api/moderation/photos/{id}`, `PATCH /api/moderation/photos/{id}` | Карточка и правка изменённых полей. Значение `null` очищает необязательное поле. |
| `POST /api/moderation/photos/{id}/decision` | `action`: `approve`, `reject`, `unpublish` или `restore`. |
| `PUT /api/photos/{id}/star`, `DELETE /api/photos/{id}/star` | Актуальные `stars` и `starredByMe`. |
| `POST /api/photos/{id}/reports` | При успехе `reportedByMe: true`. Повторная жалоба возвращает `409 already_reported`. |

После третьей активной жалобы снимок скрывается и возвращается на проверку. Статусы, счётчики и группировку серий рассчитывает Go.

## Обновления и ошибки

`GET /api/events` передаёт SSE события `map.updated` с ревизией. При событии, в том числе после переподключения, интерфейс загружает свежие метки и выбранный снимок по неизменному ID. Если временный ответ прокси закрыл поток, интерфейс подключается снова. Ответ `404` закрывает недоступный снимок и его полноразмерный просмотр.

Ошибки JSON содержат `code` и `message`. Ключи `fields`, если они есть, соответствуют полям формы. Списки публикаций и модерации обновляются при открытии панели и после действий.
