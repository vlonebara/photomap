# Подключение базы данных

Сервер открывает существующий файл `photomap.db` из рабочего каталога, проверяет его через `PingContext` и создаёт один `Store` с общим пулом `*sql.DB`. Запускать сервер нужно из каталога `server` либо командой `go -C server run ./cmd` из корня проекта.

В `main` объект store остаётся доступным для дальнейшей передачи в сервисы и обработчики. Пул закрывается после завершения HTTP-сервера. Если база не найдена или подключение не удалось, HTTP-сервер не запускается. Режим `mode=rw` не позволяет молча создать пустую базу по неверному пути.

Для каждого физического соединения драйвер применяет `foreign_keys=ON`, `busy_timeout=5000` и `synchronous=FULL`. Режим WAL сохраняется из файла базы. Встроенная версия SQLite проверяется на соответствие требованию 3.51.3 или новее.

## Новая база

Схема версии `1` сохранена в [schema/001_init.sql](schema/001_init.sql) из существующей локальной базы. Сервер не выполняет миграции автоматически. Для создания новой базы выполни один раз из каталога `server`:

```sh
sqlite3 photomap.db < db/schema/001_init.sql
```

Для уже подготовленной базы повторно выполнять этот файл не нужно.

## sqlc

Конфигурация находится в [../sqlc.yaml](../sqlc.yaml). Генерация использует сохранённую схему и каталог [queries/](queries/), результат добавляется в пакет `db`.

Версия инструмента для этого этапа — `v1.31.1`:

```sh
go install github.com/sqlc-dev/sqlc/cmd/sqlc@v1.31.1
```

Прикладные запросы сгруппированы по назначению в отдельных SQL-файлах. Сгенерированные файлы вручную не редактируются. После изменения запросов запускай генерацию из каталога `server`:

```sh
sqlc generate
```
